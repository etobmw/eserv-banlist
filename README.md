# eserv-banlist

PowerShell-скрипт, который находит IP-адреса, подбирающие пароли SMTP AUTH на почтовых серверах Eserv, и публикует список для блокировки в виде `ban.txt`. Этот файл подключается к FortiGate как External Connector (IP Address), и фаервол сам блокирует перечисленные адреса.

## Как это работает

```
Логи SMTP Eserv ──► Update-BanList.ps1 ──► ban.txt ──► веб-сервер ──► FortiGate External Connector
 (mail1, mail2)      раз в 10 минут          (IP, подсети)  (IIS)         (блокировка)
```

- **Инкрементальное чтение.** Скрипт запоминает, до какого байта дочитал каждый лог, и при следующем запуске читает только новые строки. Первый запуск читает файлы целиком (может занять несколько минут), дальше обработка занимает секунды.
- **Порог.** IP банится, если за окно `WindowHours` часов набрал `Threshold` неудачных попыток (в логе Eserv это строки `530 Auth wrong`). Время берётся из самих строк лога.
- **Срок бана.** Бан держится `BanDays` дней после последней замеченной попытки, затем снимается автоматически.
- **Белый список.** Адреса, подсети и диапазоны из `Whitelist` не банятся никогда (внутренняя сеть, внешние IP ваших фаерволов и т. п.).
- **Ручной список.** Всё, что лежит в `ban_manual.txt` (IP, подсеть `a.b.c.d/n` или диапазон `a.b.c.d-e.f.g.h`, по одному в строке), всегда попадает в `ban.txt`. При первом запуске этот файл создаётся из текущего `ban.txt`, а копия сохраняется как `ban_original_backup.txt`.
- **Сигнал о возможном взломе.** Если с IP, с которого подбирали пароль, был *успешный* вход, в `alerts.log` пишется предупреждение: учётку стоит проверить и сменить пароль.
- **Атомарная запись.** `ban.txt` сначала пишется во временный файл, а затем подменяется. FortiGate никогда не получит недописанный список.

## Требования

- Windows PowerShell 5.1 (подойдёт и более новый)
- Доступ на чтение к папкам с логами SMTP Eserv (по сети, через административные шары)
- Веб-сервер (например, IIS), который отдаёт `ban.txt` по HTTP(S)
- FortiGate с настроенным External Connector типа IP Address

## Установка

1. Скопируйте `Update-BanList.ps1` и `config.example.psd1` в любую папку на сервере, например `C:\BanList\`.
2. Переименуйте `config.example.psd1` в `config.psd1` и заполните своими значениями. Обязательны три параметра: `LogPaths`, `WorkDir`, `BanFile`. Остальное можно не трогать, значения по умолчанию описаны в файле.
3. Запустите скрипт вручную и посмотрите `update.log` в рабочей папке:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\BanList\Update-BanList.ps1
   ```

4. Создайте задание в Планировщике заданий Windows: запуск каждые 10 минут, программа `powershell.exe`, аргументы:

   ```
   -NoProfile -ExecutionPolicy Bypass -File C:\BanList\Update-BanList.ps1
   ```

   Учётная запись, от которой работает задание, должна иметь доступ на чтение логов Eserv и запись в рабочую папку и в папку с `ban.txt`.

Другой путь к настройкам можно передать параметром: `Update-BanList.ps1 -ConfigPath D:\settings\ban.psd1`.

## Настройка FortiGate

В FortiGate создайте External Connector типа **IP Address** с адресом `https://ваш-сервер/ban.txt` и интервалом обновления в несколько минут. Затем используйте его как источник адресов в правиле блокировки входящих соединений на порты SMTP. Точные названия пунктов меню зависят от версии FortiOS.

## Файлы в репозитории

| Файл | Назначение |
|---|---|
| `Update-BanList.ps1` | сам скрипт |
| `config.example.psd1` | шаблон настроек с вымышленными значениями |
| `.gitignore` | исключает из git реальные настройки и данные, которые создаёт скрипт |

## Что создаёт скрипт в рабочей папке

| Файл | Содержимое |
|---|---|
| `banned.csv` | автоматические баны: IP, первая и последняя попытка, число попыток |
| `pending.csv` | IP, которые набирают попытки, но ещё не достигли порога |
| `offsets.csv` | до какого байта прочитан каждый лог |
| `ban_manual.txt` | ручной список, редактируется вручную |
| `update.log` | журнал работы скрипта (ротация при размере больше 5 МБ) |
| `alerts.log` | предупреждения об успешном входе с подозрительных IP |

## Если у вас другой формат лога

Скрипт рассчитан на строки вида `дата время;IP;учётка;сообщение`. Признак неудачной авторизации (`FailPattern`) и код успешной (`SuccessPrefix`) задаются в настройках, так что для другой версии Eserv или для другого почтового сервера с похожим форматом достаточно поправить `config.psd1`. Если формат строки отличается, придётся править блок разбора строки в самом скрипте.

## Безопасность

- Никогда не коммитьте `config.psd1`, `*.csv`, `*.log` и `ban.txt`: в них реальные адреса и имена учёток.
- Не публикуйте реальные пороги срабатывания и белый список: они подсказывают атакующему, как остаться под порогом и какие адреса у вас не блокируются.
- Если вы всё же закоммитили секретные данные, удаление файла следующим коммитом не поможет, данные останутся в истории. Меняйте скомпрометированные значения.
